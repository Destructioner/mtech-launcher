# M-Tech Launcher Ecosystem

Полноценная экосистема для запуска и авторизации игроков на приватном Minecraft-сервере (Fabric). Проект включает в себя десктопный клиент, сервер авторизации и игровой мод, общающиеся по кастомному бинарному протоколу.

## 🏗 Архитектура системы

Система состоит из трех независимых компонентов:

1. **C++ Qt Client (Launcher)** — десктопное приложение для загрузки ассетов, проверки HWID и запуска игры.
2. **Python Asyncio Auth Server** — асинхронный сервер авторизации с шифрованием трафика (TLS) и безопасным хешированием паролей (`scrypt`).
3. **Java Fabric Mod** — мод, перехватывающий сетевой стек Minecraft через Mixin-инъекции для проверки активной сессии игрока перед входом на сервер.

_________________________________________________
[Qt Client (C++)] 
      | (TLS / Custom Binary Protocol)
      v
[Python Auth Server] <---> [SQLite Database]
      ^
      | (TLS)
[Fabric Mod (Java)]
_________________________________________________



🛠 Стек технологий
Клиент: C++17, Qt6 (Network, Concurrent, Widgets), WinAPI (SMBIOS, HWID), QuaZip.

Сервер: Python 3.10+, asyncio, ssl, hashlib (scrypt), aiofiles, mcrcon.

Мод: Java 17, Fabric API, Mixin (перехват логина).

🚀 Реализованные фичи
Кастомный бинарный протокол обмена данными поверх TLS.

Аутентификация по HWID: сбор уникального идентификатора оборудования (MAC-адрес + серийный номер материнской платы через WinAPI/SMBIOS).

Защита от мультиаккаунтинга: привязка игрового аккаунта к конкретному железу.

Многопоточная загрузка: асинхронное скачивание клиента, библиотек и ассетов Minecraft с контролем потоков (QSemaphore, QMutex).

Автоматическая установка модов: парсинг Google Drive для загрузки и распаковки модпака.

Интеграция с RCON: автоматическое добавление игрока в вайтлист сервера при успешной регистрации.

⚠️ Известные проблемы и Roadmap
Проект находится в активной разработке. Текущие задачи:

□ Уязвимость (Session Hijacking): текущая реализация сессий уязвима к перехвату. В планах: переход на JWT-токены с временем жизни.
□ Перенос хранения сессий из памяти сервера в Redis (для устойчивости к перезапускам).
□ Добавление таймаутов на чтение сокетов на стороне Python-сервера.
